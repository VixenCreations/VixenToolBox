Under the hood of the Vixens Toolbox ecosystem. A technical breakdown of the heuristics, math libraries, procedural pipelines, and real-world implementation driving the editor utilities.

Vixen Hub & DOM Bridging

VixenHub.cs

The flagship entry point. Engineered to entirely bypass legacy OnGUI redraw lag, the Hub utilizes a custom Markdown-to-UIToolkit Parser. It autonomously reads repository manifests and dynamically spawns native VisualElements, maintaining layout stability without locking the Editor thread.

  • Autonomous Scene HUD: Injects a sleek, non-blocking >> VIXENS TOOLBOX UPDATE notifier directly into the Unity Scene View via Handles.BeginGUI(). This passively monitors state via an [InitializeOnLoad] hook, completely preventing workflow-breaking popups.
  • Action Delegate Routing: Overhauls markdown rendering by parsing [text](url) syntax mid-paragraph. It dynamically spawns transparent Button elements inline, mapping standard URLs to Application.OpenURL and custom internal commands directly to C# System.Action delegates.

In Practice: The Workflow

  • Interface Execution: Accessible via Vixens Toolbox > Hub Dashboard, the interface successfully translates the web's neon-pink/cyan aesthetic into Unity's native Editor styling.
  • Live Parsing: The tool autonomously extracts the exact ecosystem version natively from package.json and parses CHANGELOG.md into highly readable UI Toolkit sections without horizontal scrolling constraints.

Avatar Optimization Suite

VixenAvatarValidator.cs | VixenMeshPatcher.cs

A multi-threaded, highly destructive execution designed to violently crush PC avatar polycounts and physics limits. It dynamically analyzes your hardware footprint and deploys a custom spatial hashing algorithm to decimate geometry while mathematically protecting high-fidelity facial topology.

  • Vertice Mesh Welder: Fuses co-located vertices on excessively heavy meshes (>15,000 polygons) by generating a proprietary 5-dimensional coordinate key. By mapping XYZ position natively alongside U and V coordinates, it drastically crushes raw polycounts while mathematically guaranteeing the survival of critical texture seams.
  • Dual-Shielding Exclusion: Automatically scans submesh material slots for high-detail keywords (e.g., eyes, visor, face) AND actively queries the active Humanoid Armature for HumanBodyBones.Neck. Any vertex influenced by these kinematics is locked entirely out of the decimation grid.
  • BlendShape Memory Recovery: Executing a destructive mesh wipe inherently annihilates Unity's blendshape delta arrays. The Welder caches all 175+ frames (visemes, facial expressions) prior to execution and mathematically averages the delta offsets across the newly fused vertices, allowing animations to perfectly survive aggressive topology meltdowns.
  • Kinematic Bounding Box Stabilization: Solves the bounding-box disappearance bug by encapsulating all 8 corners of the sharedMesh.bounds into absolute World Space, then projecting them backward into root-bone Local Space for a mathematically perfect, tight-fit bounds calculation.

In Practice: The Workflow

  • Dynamic PC Target Rank: Eradicates static culling limits. Creators explicitly target specific VRChat Performance Ranks (Excellent, Good, Medium, Poor) via a native dropdown. The deep-scanning heuristics instantly recalibrate execution thresholds for Animators, Contacts, and PhysBones based on the selected hardware constraints.
  • Interactive Physics Executioner: Replaces invisible auto-cull algorithms with a surgical UI Toolkit panel. Spawns an interactive mapping every physics component sorted by hierarchy depth. Creators manually select and eradicate expendable leaf-node physics (tail fluff, hair tips) while visually protecting structural roots.
  • Deep Material Inspector Spider: Pierces through the Unity Inspector using EditorUtility.CollectDependencies. It spiders through Animator controllers and VRCFury outfit toggles, aggressively hunting down and caching nested textures to ensure the VRAM calculator and ImageMagick downsampler capture 100% of the avatar's actual memory footprint.

Quest Conversion Engine

QuestConversionEngine.cs

A highly optimized, non-destructive pipeline engineered to mathematically evaluate and map VRChat Mobile Performance ranks natively. The system isolates your avatar into a temporary conversion sandbox, ensuring your original PC prefab is never mutated or irreversibly altered.

  • Magick.NET Linear Downsampling: Intercepts all detected textures and processes them through a high‑fidelity Lanczos filter. Textures are temporarily shifted into ColorSpace.RGB (Linear) to prevent highlight crushing during scaling, followed by a precision-tuned UnsharpMask(0.0, 0.5, 1.0, 0.05) pass to restore micro‑detail typically lost in Android ASTC compression.
  • Base‑Class Heuristic Culling: Deep‑scans all <VRCPhysBoneBase> derivatives to capture 100% of physics variants, including VRCFury auto‑conversions and legacy migrations. The engine recursively purges globally banned mobile components such as Cameras, AudioSources, and Constraints.
  • IgnoreTransform Shield Piercing: Reads and interprets every ignoreTransforms array inside PhysBone components. If a bone is explicitly listed, the shield is dropped, allowing the culling to correctly identify and remove dead leaf‑node bones that would otherwise survive heuristic filtering.
  • Deep Material VRCFury Cloning: Uses SerializedObject stream traversal to locate hidden materials inside VRCFury toggles, blend‑trees, and state behaviors. All discovered references are remapped to newly generated Android‑safe material variants, preventing pink‑shader failures at runtime.
  • Face Tracking & VRCFT Hunter-Killer: Three-vector detection sweep catches PC-VR face tracking before it reaches the Android build pipeline: (1) prefab path match against adjerry91.vrcft.templates, (2) hierarchy name match against VRCFury - Face Tracking and VF_UE_VRCFT branches, and (3) namespace/type match against VRCFT, FaceTracking, and adjerry91 components. Hits are routed into a locked auto-cull list with neon-red, non-overrideable toggles so they're visible for forensic review but cannot be accidentally retained.
  • Mobile Shader Targeting: After material cloning, all materials are auto-converted to a selected Quest shader - VRChat/Mobile/Toon Standard, VRChat/Mobile/Toon Lit, VRChat/Mobile/Standard Lite, VRChat/Mobile/MatCap Lit, or Unity's Mobile Standard - with minor adjustments to restore visual parity (resetting emission maps, applying Multiply blending to particle lenses, enabling Additive on visors).

In Practice: The Workflow

  • Selective Macro Culling: After scanning, the interactive topology populates with all detected components. Global Keep All and Cull All macros allow creators to rapidly triage large arrays, preserving structural bones while discarding expensive fluff such as tail tips and hair strands.
  • Post‑Conversion Material Tweaks: The engine defaults all materials to mobile‑safe shaders such as VRChat/Mobile/ToonLit. After cloning, minor adjustments restore visual parity-resetting emission maps, applying Multiply blending to particle lenses, and enabling Additive rendering on visors to recover transparency.
  • Bypassing Artificial Blocks: When a “Very Poor” rating is caused solely by the immutable 20,000‑triangle cap rather than actual optimization issues, the engine exposes a bypass allowing creators to compile the avatar anyway for showcase or testing purposes.
  • Root Animator Protection: A recursive depth scanner identifies the avatar’s core root Animator and hard‑locks it, ensuring heuristic culling never destroys locomotion controllers, FX layers, or toggle logic.

PhysBone Topology Mapper

PhysBoneTopologyMapper.cs | PhysBoneBlueprint.cs

Designed to eliminate the human error of manually dragging, dropping, and configuring colliders across avatar iterations. This engine entirely decouples the physics from the mesh hierarchy by snapshotting your PhysBone architecture into reusable blueprints.

  • Master Blueprints: Utilizes AnimationUtility.CalculateTransformPath to generate relative skeletal paths from a chosen avatar root. Each VRCPhysBone is serialized into a Unity Preset and stored in a custom PhysBoneBlueprint ScriptableObject, mapping bonePath → Preset with surgical precision.
  • Two-Phase Architecture: Phase 1 ("Extract Master Copy") walks the source avatar, generates presets under Assets/VixenTools/Blueprints/<Name>/Presets, and writes a master .asset blueprint. Phase 2 ("Inject Blueprint") traverses a target avatar by relative path, auto-adding VRCPhysBone components where missing and applying the stored presets.
  • Graceful Degradation: When the VRChat SDK is not present, the window falls back to a safe visual state. All destructive buttons are disabled and clearly labeled as SDK-dependent, preventing accidental misuse in non-VRChat projects.

In Practice: The Workflow

  • Creating the Blueprint: A creator selects their master PC avatar root and runs "Extract Master Copy". This recursively catalogs every physics script and saves it to a structured blueprint (e.g., Assets/VixenTools/Blueprints/Avatar_MasterTopology).
  • Restoring Stripped Physics: If an avatar has had its components stripped (such as during manual Quest conversion or destructive optimization), the user selects the stripped avatar and hits "Inject". The mapper autonomously traverses the skeletal structure and reapplies the data. For instance, injecting the blueprint can perfectly restore dozens of distinct physics presets accurately across the entire rig in a single click.

Animator Forge

VixenAnimatorForge.cs | AnimatorDoctor.cs | RigForge.cs

A two-sided avatar animator tool. The Doctor scans every playable-layer controller plus the Expression Parameters and Menu and reports ranked findings with one-click fixes. The Forge builds complete, fully-wired rigs (parameter, menu control, FX layer, states, transitions and clips) from a single form. Both halves are non-destructive by construction.

  • Ranked Finding Model: Every diagnostic is emitted as a finding carrying a Severity (Error, Warning, Info), a title, a detail string, a context object, an IsSafe flag, and an optional Fix delegate. The UI renders a LOCATE button per finding that drives EditorGUIUtility.PingObject onto the offending asset, plus a FIX ALL SAFE ISSUES batch that runs only the findings where IsSafe && Fix != null, leaving every judgement call to the creator.
  • Driver-Parameter Recognition: Controllers that reference parameters which were never declared are the single most common source of SDK panel spam on a purchased base. The Doctor separates the two cases: parameters VRChat itself provides at runtime (Seated, AFK, VRMode, GestureLeft/GestureRight and the rest of the driver set) are re-added to the controller with the correct type, while genuinely undefined parameters are reported rather than invented.
  • Write Defaults Normalizer: Detection follows the widely-used VRCFury model. States are grouped as normal, Direct blend tree, or additive; the target value is taken from the FX layer's majority (falling back to the avatar-wide majority on smaller rigs); and normalization always forces Direct blend trees and additive layers on, because those break otherwise. The exact offending states are named in the report and nothing is written until asked.
  • Empty-Clip Repair: Reproduces VRChat's own scan for the "Write Defaults disabled where the animation clip is either missing or empty" warning. MotionHasEmptyIssue walks blend trees recursively, so a Direct tree with one empty child is caught as readily as a bare null motion. The fix assigns a shared inert clip from Assets/VixenTools/AnimatorForge/_Empty.anim carrying a single constant m_IsActive curve, which is what actually clears the warning: a genuinely empty clip still reads as empty to the SDK.
  • Expression Asset Auditing: Cross-checks the Expression Parameters and Menu against the controllers. It catches duplicate parameter names, type mismatches between a controller and the expression asset, synced cost overflow against VRCExpressionParameters.MAX_PARAMETER_COST, menus exceeding VRCExpressionsMenu.MAX_CONTROLS, SubMenu controls with a null target menu, controls with no parameter at all, and controls bound to parameters that were never declared.
  • Layer & Transition Hygiene: Flags duplicate layer names, layers with no states, layers with no default state, layers sitting at weight 0, transition conditions using a comparison mode invalid for the parameter's type (for example Greater on a Bool), and instant zero-duration transitions.
  • Five Rig Types: GameObjectToggle (one or many objects at once), BlendshapeToggle, BlendshapeSlider (a radial-puppet dial), MaterialSwap, and ExclusiveGroup, a radio set where enabling one option drives the rest off. Each build generates the Expression parameter, the menu control or submenu, the FX layer with its states and transitions, and the animation clips.
  • Convention Matching: New states are created to match the avatar's own Write Defaults convention rather than a hardcoded default, so a forged toggle does not become the one odd state that desyncs an otherwise consistent controller.
  • Non-Destructive Asset Handling: Reuses an existing FX controller and expression assets or creates them when absent, clones read-only sample controllers before touching them, and never deletes existing layers or parameters. Generated assets land in Assets/VixenTools/AnimatorForge/<AvatarName> via a step-through IsValidFolder → CreateFolder chain.

In Practice: The Workflow

  • Triage On A New Base: A freshly purchased avatar is dropped into the Doctor tab and scanned. The typical first result is a cluster of missing driver parameters on the Sit and Action layers plus a mixed Write Defaults report. FIX ALL SAFE ISSUES clears the unambiguous parameter findings in one pass; the Write Defaults normalization is reviewed and applied separately because it changes animation behavior.
  • Clearing The SDK Panel: Where the SDK complains about Write-Defaults-off states with missing or empty clips, the empty-clip fix assigns the shared inert clip across every offending state, and the warning clears on the next build check.
  • Forging A Toggle: On the Forge tab the creator names the rig, picks GameObject toggle, drags in one or several objects, and builds. The parameter, the menu entry, the FX layer, both states and both clips are generated together and matched to the avatar's existing Write Defaults convention, so the toggle works on the first upload without hand-wiring the Animator.
  • Exclusive Outfit Sets: For a set of mutually exclusive outfit pieces the Exclusive group type generates an Int parameter with one state per option, so selecting one drives every sibling off. This is deliberately an Int plus toggles rather than a radial, because landing exactly on option three with a thumbstick is miserable.

Accessory Mounting Engine

AccessoryArmatureCloner.cs

Clones sterile armatures from a source rig and surgically mounts accessories onto the resulting hierarchy. Built to eliminate the manual labor of rigging convention props, conditional outfit pieces, and rigid attachments by collapsing a multi-step destructive workflow into a single deterministic pipeline pass.

  • Dual Pipeline Modes: FullGeneration clones a fresh sterile armature out of the source hierarchy using a recursive CloneHierarchy pass that preserves local TRS at every node. AppendToExisting skips cloning entirely and uses AnimationUtility.CalculateTransformPath to resolve relative bone paths against an existing sterile rig, letting creators seamlessly append new accessories to a previously generated target without rebuilding the armature.
  • Destructive Auto-Rig Strategy: For soft/deforming meshes, every child SkinnedMeshRenderer and MeshFilter in the accessory hierarchy gets gathered, deduplicated, and baked individually. Each mesh receives a per-child Matrix4x4 localToBoneOffset = sterileBone.worldToLocalMatrix * target.localToWorldMatrix transform that's applied to vertices, normals, and tangents. Blend shapes are fully preserved every frame's deltaV/N/T arrays are transformed through the same offset and rebuilt onto the baked mesh.
  • Kinematic Constraint Strategy: For rigid prefabs, particles, and audio sources, skips the bake entirely and applies a ParentConstraint with surgically calculated position/rotation offsets (sterileBone.InverseTransformPoint(...) and Quaternion.Inverse(sterileBone.rotation) * accessoryRoot.rotation), then locks the constraint to preserve the exact visual placement at mount time.
  • PhysBone-Safe Root Lock: The auto-rig path deliberately does not zero the accessory root's transform after baking. Instead, it parents the root under the target rig and applies the same locked ParentConstraint as the kinematic strategy, preserving any PhysBone hierarchies that depend on a non-zeroed root for inertia and anchor calculations.
  • Single-Bone Rigid Bind: Baked meshes are bound to a single bone (boneIndex0 = 0, weight0 = 1f) with bindposes set to Matrix4x4.identity. The resulting SkinnedMeshRenderer swap is in-place: existing MeshFilter and MeshRenderer components are undo-destroyed and replaced with a fresh SMR carrying the original materials.
  • Culling-Resistant Bounds: Baked meshes ship with SkinnedMeshRenderer.localBounds forced to a 2.5m cube around origin, preventing Unity from aggressively frustum-culling accessories whose vertex data has been transformed into bone space.
  • Step-Through Asset Persistence: Baked meshes serialize to Assets/VixenTools/Meshes/BakedAccessories/ with GUID-suffixed names to prevent collision across runs. The folder bootstrap uses a step-through IsValidFolder → CreateFolder chain so the path resolves cleanly on fresh installs where neither Assets/VixenTools nor its children exist yet.
  • Full Undo Integration: Every bone clone, component swap, constraint binding, parent re-route, and mesh swap is wrapped in Undo.* calls and collapsed into a single undo group, so a single Ctrl+Z rewinds the entire pipeline execution.

In Practice: The Workflow

  • First-Pass Mount: The creator drops their source avatar's armature root into Source Armature, drops the destination GameObject into Target Accessory Root, and adds each accessory prefab with its desired target bone in the Accessory Mappings list. FullGeneration + DestructiveAutoRig then clones a sterile rig, bakes the accessories, and parents the result under the target all in a single click.
  • Appending Without Re-Cloning: When new accessories ship later (a convention badge, a seasonal prop), switching to AppendToExisting reuses the already-generated sterile armature inside the target. The mapper resolves bone identities by relative path, so mappings made against the original source rig still resolve cleanly without touching the already-mounted accessories.
  • Mixing Strategies Per-Mount: Because the strategy is selected at execute time and the constraint logic is shared between both paths, a creator can run the engine multiple times against the same target DestructiveAutoRig for a deforming cloth piece, KinematicConstraint for a rigid badge and the resulting target carries a consistent mix of baked SMRs and constrained rigid roots.

Animation Workbench Pro

AnimationWorkbenchWindow.cs | PreviewEngine.cs | CurveGraphView.cs | CurveOperations.cs | EasingFunctions.cs | MaterialPropertySearchPopup.cs | EasingDropdown.cs | TimelineRibbon.cs

An advanced visual workspace for staging, easing, and sampling complex animation curves, built to bypass Unity's clunky default Animation window completely. The Workbench treats curves, bindings, and material properties as a programmable instead of a fragile hand-drawn timeline.

  • Runtime Math Library & Easing: Mathematical keyframe generation driven by EasingFunctions.cs. CurveOperations.BuildStretchedCurve rebuilds a curve between [sTime, eTime], preserving keys before the region while injecting intermediate keys using selectable easing (Linear, SmoothStep, EaseInOutCubic, etc.). Keys after the region are intentionally dropped, letting the generated segment define the tail.
  • CurveGraphView Engine: A custom VisualElement graph powered by IMGUIContainer. Supports zooming, panning, double-click key insertion, and right-click key deletion with per-binding color hashing. It computes dynamic value ranges and renders both continuous curves and discrete key markers.
  • Live Preview Engine: PreviewEngine hooks into AnimationMode.StartAnimationMode() and EditorApplication.update to sample clips directly on a target GameObject. It plays back at adjustable speed, stops automatically at clip end, and never dirties the scene hierarchy.
  • TimelineRibbon Range Control: A dedicated IMGUI ribbon that exposes start/end sliders for the active clip. It prevents zero-length collapse, supports expanding beyond clip length, and broadcasts range changes back into the graph and generation logic.
  • Multidimensional Material Extraction: The Workbench walks all renderers on a preview target, inspects shader properties, and explodes Color/Vector fields into per-channel float tracks (R/G/B/A, X/Y/Z/W). This prevents native API crashes and makes even locked Poiyomi properties fully animatable.
  • MaterialPropertySearchPopup: A dedicated search window that groups properties by Material → Category → Property. It supports fuzzy search, nested foldouts, and click-to-bind behavior, returning a structured entry back to the Workbench.
  • EasingDropdown Selector: A lightweight UI Toolkit control backed by GenericMenu. It renders textual previews of easing shapes and broadcasts changes via OnValueChanged, allowing global default easing to be applied across all selected bindings.

In Practice: The Workflow

  • Hidden Property Discovery: The MaterialPropertySearchPopup is utilized to read directly from a shader's active parameters. For example, it allows a creator to easily locate an obscure third-party property like _LumaFlowSpeed and extract its exact resting value (e.g., 0.00121).
  • Mathematical Smoothing: Rather than manually dragging bezier curves, a creator inputs the exact start and end values, selects a mathematical easing profile (e.g., SmoothStep), and defines key density. Generating 40 keys over 3 seconds creates a perfectly smooth stepped curve instantly.
  • Iterative Prototyping: The timeline can be scrubbed live via the PreviewEngine. If the animation feels too fast, the user can instantly re-generate the curve with 80 keys spread over 6 seconds, visually verifying the ultra-smooth transition directly in the editor without launching Play mode.
  • Explicit Intent Safeguards: Staged curves are held in an internal dictionary until the user explicitly applies or commits them. This prevents accidental destructive writes to live clips and keeps experimentation reversible.

Vixen Badge Studio

VixenBadgeMaker.cs

A high-fidelity, CSS-driven procedural generation utilizing a native JSON layout engine (layout.json) to architect multi-channel convention badges dynamically, specifically heavily targeting Furality templates.

  • Emissive Compositing Math: Fixes native Unity Standard Shader bloom blowouts. ImageMagick renders the generated text onto a pure MagickColors.Black background and mathematically flattens the output, permanently stripping the alpha channel before exporting the _EMI map to guarantee zero-bleed emission.
  • Universal Shader Injection: Automatically detects target shaders (Poiyomi, lilToon, VRC Mobile) and physically reaches into the compiled material to force-write user-selected Base and Emissive colors directly into the _Color and _EmissionColor slots.
  • Interactive Raycasting (UV Mapper): Temporarily suspends Unity gizmos and hijacks the Scene View. Raycasts against the MeshCollider, mathematically inverting 3D hits into 2D ImageMagick pixel space for perfect custom coordinate mapping.

In Practice: The Workflow

  • Automated Ingestion: After downloading the Furality SDK, the "Generate Furality JSON Layouts" button runs a Regex search algorithm to detect all convention badge components and builds strict spatial boundary rules (JSONs) for text injection autonomously.
  • Dynamic Shader Swap: Allows real-time transition of underlying shader properties. Switching a badge from a Standard shader to "Furality Aqua" recompiles the material on the fly, accurately placing the generated Diffuse and Emission textures into the new proprietary shader slots.
  • Live UV Repositioning: If a creator needs to adjust text placement, they don't need Photoshop. Activating the "Scene Mapping" raycaster attaches a temporary Mesh Collider. The user simply clicks on the badge in 3D space, which copies the X/Y intersection. Modifying the Width/Height bounds and recompiling uses ImageMagick to instantly expand and move the generated text.

Core Scene Utilities

BulkPresetGenerator.cs | SnapToSurface.cs | FixSceneData.cs

A high-performance suite of background operations and spatial automation scripts engineered to enforce structural integrity, optimization standards, and geometric precision across the Unity workspace.

SPATIAL TOPOLOGY TOOLS

  • Live Surface Snapping (Dual-System Gravity): Utilizes low-overhead Transform.hasChanged tracking to simulate autonomous gravity for objects moved via the transform gizmo. It calculates bounding-box nadirs on the fly to drop assets perfectly flush with underlying geometry the moment the mouse is released.
  • Precision Click-to-Place Raycaster: A sniper-rifle camera raycaster enabling creators to paint/teleport objects onto complex shelf polygons or terrain. Guided by a cyan/magenta UV projection disc, it calculates surface normals to instantly align selected assets with 100% geometric accuracy.
  • Surgical Shielding & VRC-Layer Masking: Features a bitwise layer mask (~((1 << 2) | (1 << 4)...)) to explicitly ignore VRChat-specific utility layers (Water, UI, Pickup, etc.). It autonomously caches and disables child colliders during execution to prevent self-occlusion deadlocks.

INFRASTRUCTURE & RECOVERY

  • Pipeline Preset Manager (BulkPresetGenerator.cs): A unified pipeline tool that handles both bulk extraction of presets from existing assets and programmatic authoring of standardized importer presets using a Phantom Asset architecture. It exposes two modes: Extraction Pipeline and Authoring Engine, switchable via neon-styled tabs.
  • Bulk Preset Extraction: Rips component configurations from selected GameObjects (optionally including children) into reusable Preset assets. It can ignore Transform components, auto-register new presets into Unity's Preset Manager, and names files by object and component type for instant traceability.
  • Phantom Asset Authoring: Programmatically authors standardized texture importer presets without needing a source asset. It generates a temporary PNG "Phantom" texture, configures TextureImporter (type, max size, mipmaps, readability), then rips that configuration into a permanent Preset and injects it into the Preset Manager with an optional glob filter (e.g., glob:"**/*_BaseColor.png").
  • Preset Manager Injection: Uses Preset.GetDefaultPresetsForType and Preset.SetDefaultPresetsForType to prepend new defaults, ensuring newly imported assets automatically conform to your global standards (NormalMap flags, ASTC caps, mip rules) without manual configuration.
  • Udon State Serialization: Snapping logic is tied directly into the Udon Virtual Machine via EditorUtility.SetDirty. This ensures that snapped objects hosting UdonBehaviour components correctly register hierarchical changes, preventing catastrophic position rollbacks during world builds or network syncs.
  • Lightmap Serialization Engine: FixSceneData.cs actively forces the re-serialization of lightingDataAsset references within the EditorSceneManager, fixing the notorious issue of black or missing lightmaps when transferring scenes between systems via VPM.

In Practice: The Automated Workflow

  • Spatial Triage: By establishing a 1024px ASTC phantom preset, the tool forcefully injects memory boundaries into Edit > Project Settings > Preset Manager. Every subsequent file conforms to these rules. Simultaneously, SnapToSurface.cs ensures that every asset spawned into the scene conforms to the environment's physical limits, using dynamic iteration to locate the absolute minimum global Y-bound across all mesh renderers and child colliders.

Vixen World Engine

VixenWorldSpider.cs • VixenHeuristicsDashboard.cs • VixenEngineStressTest.cs • ShaderDictionaryAsset.cs

Operating on a deep-reflection layer, the engine pierces Unity, Udon, and third‑party assemblies to expose hidden performance traps long before they detonate in a live instance.

  • IwaSync3: Flags 1080p+ video blowouts, unbounded playlist growth, global non‑spatialized audio, aggressive sync frequencies, emissive screen overdrive, and GC‑heavy event invokers.
  • TXL Logic Scraper: Detects starvation‑level polling (monitorTriggerInterval = 0.01f), collapsed translation tables, forced collider checks, orphaned Udon behaviours, and cryptographic sinks from DigestValidator.
  • Mesh & Geometry Hunter: Identifies 66k+ vertex meshes, missing LOD chains, non‑convex MeshCollider drag, realtime reflection probes, and physics sinks that destabilize frame pacing.
  • Stress Test Fabricator: Generates a full Omni‑Chaos environment with realtime lights, reflection probes, VRAM nukes, 4K textures, heavy meshes, network sync storms, and video pipeline overloads.
  • Lighting & Camera Auditor: Ensures world descriptors, spawn points, and baseline lighting exist, preventing SDK validation failures and broken world boot sequences.
  • VizVid (VVMW) Pipeline Audit: Identifies cross-platform AVPro fallback failures, missing RateLimitResolver instances, decoupled UI/Frontend handlers, and spatialized audio bleed across multi-screen setups.
  • Rinvo Search Ecosystem: Re-aligns mismatched VideoPlayer UI target enums, enforces proxy addition rules, and clamps API pool sizes to prevent Udon network rate-limit nukes from the YouTube search backend.

UI, SECURITY & MEMORY SENSORS

  • Raw UASM Scraper: Intercepts UdonSharpEditorCache to analyze raw Udon assembly. Detects lethal PlayerData.Set calls inside Update(), infinite sync loops, and network‑rate‑limit bombs before they reach a build.
  • UI & Font Integrity: Flags deprecated Arial.ttf, mismatched TMP assets, missing shader channels, and world‑space canvases that trigger rebuild cascades.
  • Shader & Asset Whitelist: Protects core SDK shaders, IwaSync internals, ProTV internals, and VRC Billiards materials from the autonomous shader replacer.
  • Hardware‑Level VRAM Security: Uses Profiler.GetRuntimeMemorySizeLong() to capture true GPU footprint, exposing procedural 4K RenderTextures, TMP atlases, UI masks, and hidden memory hogs.
  • Canvas Rebuild Tracker: Detects layout‑modifying elements on root canvases, preventing catastrophic rebuild storms in playlist UIs and queue systems.
  • Video Pipeline Throttling: Monitors video players, sync frequencies, and networked playback logic to prevent runaway bandwidth usage and frame pacing collapse in high-traffic instances.
  • LTCGI / Light Volumes / AudioLink Audits: Resolves BakeInProgress NRE deadlocks, detects fragmented LTCGI memory arrays (ghost screens), and auto-links missing video output textures. Flags multiple AudioLink core collisions, Quest GPU readback stalls, unlinked reactive objects, and unsafe TVGI strobe/flicker thresholds on Light Volume rigs.
  • World Profiler Dashboard (VixenHeuristicsDashboard.cs): Standalone heuristics window that aggregates texture, mesh, audio, UI, lightmap, LTCGI, AudioLink, video, physics, and Udon footprints in O(1) via the _sceneObjectCache + _textureRecoveryCache. Computes a threat score that heavily penalizes realtime shadow casters (80x weight) and surfaces an at-a-glance OPTIMAL / MODERATE / SEVERE verdict.
  • Shader Dictionary Auto-Population: ShaderDictionaryAsset + its custom editor expose three buttons - Populate Targets, Populate Whitelist, and Factory Reset (Nuke & Rebuild). Dictionaries auto-generate inside Assets/VixenTools/Asset Database/World Engine/ (not inside Packages/) so custom entries survive VPM upgrades. The Soft Nuke path bypasses AssetDatabase.DeleteAsset to avoid GUI null-reference collapses during a rebuild.
