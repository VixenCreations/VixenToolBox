Stream Connector v6.3.0: The Manifesto

1. Philosophy & Reality Check

No Telemetry | Full Control
"This project doesn’t exist to be polite. It exists to give you control. Not platform control. Not corporate control. Your control."

Stream Connector is built for intimacy, high-control use, and uncompromised power dynamics. It does not judge, and it does not use training wheels.

  • Why Tiering Died: Locking power behind paywalls helps nobody. If you are trusted to run this software, you are trusted to use all of it. Platforms change rules overnight; this app is yours to keep.
  • Privacy by Default: No telemetry. No cloud dependency. No accounts. No hidden behavior. Everything is deliberate, reversible, and stops when you say stop.
  • VRChat Avatar Control: Your avatar stops being decorative and becomes reactive. Toggle clothing, chain visual states, and keep everything deterministic via OSC.

2. Security & Network Architecture

Local-First | Fail-Closed

If you’re paranoid: good. This architecture is designed to be fully auditable. Stream Connector is local-first, explicit-by-design, and has zero inbound internet exposure.

  • Fails Closed, Not Open: Includes global execution locks, busy-state enforcement, rate limiting, and hard stop paths. If the engine cannot validate state, it stops. It does not enter infinite spam loops.
  • Antivirus Trust: All builds are cryptographically signed. There is no obfuscation, no remote scanning, and no hidden updaters. If your AV complains, it is because this software controls real hardware and opens sockets, not because it is malicious.
  • Outbound Only (PiShock): PiShock requires internet because it is a brokered platform. However, the app only utilizes outbound HTTPS/WSS to the broker. No inbound ports are opened on your machine.

4. Tri-State Concurrency Engine

asyncio | ThreadPoolExecutor | Tkinter

Engineered to survive massive broadcast payloads (10,000+ viewer raid alerts) without causing the UI thread to stall or dropping execution packets.

  • The Capture Buffer: Incoming events are piped into a thread-safe collections.deque(maxlen=5000). This acts as a shock absorber. Instead of locking the OS socket, the app processes the queue sequentially.
  • Hardware Offloading: Blocking REST calls and heavy logic are forcefully punted to a ThreadPoolExecutor(max_workers=6), guaranteeing the Tkinter mainloop never hangs.

5. Developer Integrations (Streamer.bot & API)

Port 8080 (WS) | Port 8840 (HTTP)

Because walls are for people afraid of power. The connector exposes rigorous, typed endpoints allowing third-party integration without compromising the security model.

// The Core Execution Hook routing all external events
execute_external_hook(provider, command_id, context)
  • Streamer.bot (WS): Connects via ws://127.0.0.1:8080/. Uses an Example Sub Action.cs script to fire valid, perfectly-escaped JSON over the internal WebSocket without expecting a callback, ensuring zero execution drag on the broadcast software.
  • External HTTP API: Waitress WSGI server listening on http://127.0.0.1:8840. Accepts strictly typed JSON at /api/external/exec. Payloads are passed through untouched—no eval, no execution, just safe structured data routing. Errors always return HTTP 200 to avoid breaking bots.

6. Haptic Abstraction Layer (HAL)

PiShock | Intiface (v3) | OWO Suit | OSC

The connector normalizes vastly different hardware protocols into a single, unified internal schema, allowing users to map one chat event to multiple discrete devices simultaneously.

  • Intiface (Buttplug.io): Directly parses the Buttplug v3 JSON schema. Autonomously listens to DeviceAdded messages and natively maps capabilities (VibrateCmd, LinearCmd).
  • PiShock REST Dispatch: Bypasses local network restrictions by serializing payloads directly to the PiShock API.
  • OWO BLE Integration: Intercepts the official OWO.dll via pythonnet. Maps abstract arrays (e.g. [Pectoral_R, Abdominal_L]) to raw sensation strings.
  • OSC Translation: Native UDP implementation routing standardized float values seamlessly into VRChat avatar parameter spaces.

Development & Diagnostics Suite

The complete set of standalone reconnaissance tools, packet sniffers, and CI/CD harnesses engineered during the R&D phase to reverse-engineer hardware protocols and validate bridge stability.

Hardware Reverse-Engineering & Reconnaissance

BLE-DeepProbe.py

Utilizes bleak to map OWO Suit GATT characteristics. Autonomously negotiates the 0*AUTH* handshake, maintains a strict 0.5s 0*PING* keepalive loop, and writes raw sensation vectors directly to the Write UUID to eliminate native driver latency.

Process.py (Socket Ripper)

When local UDP discovery fails, this uses psutil to hunt for the proprietary myowo_flutter.exe process natively. It violently rips its active TCP/UDP bindings to forcefully establish connection lines.

ServiceSpy.py

Implements a zeroconf browser that passively monitors the local network for DNS-SD broadcasts. Used to decrypt mDNS routing and dynamically map service properties and IPv4 locations of headless haptic nodes.

BLE-OWOTest.py & BLE-PacketTest.py

Twin stability harnesses. OWOTest.py maintains the asynchronous keepalive and 8-second re-auth loops, while PacketTest.py focuses entirely on verifying the structural integrity of the 0*GAMEAVAILABLE* payload drops.

API, WebSocket, & Schema Validation

TestPayload.py

The official CI/CD REST test harness. Generates UUIDs for every dispatched request against port 8840. Tests multi-step command chains and verifies HTTP status codes to ensure the internal Waitress server remains stable under attack.

TestPayloadStreamerBot.py

A direct WebSocket injector for Streamer.bot (Port 8080). Autonomously fires GetActions and GetGlobalVariables frames to dump and map Streamer.bot's internal data structures, verifying the bridge has complete bi-directional context.

ProbeSchema.py

A Buttplug.io v3 specification stress-tester. Systematically hits the Intiface Central socket with Object-Keyed, Array-Keyed, and Explicit Type payloads to determine the exact parser logic required for integration.

TestIntiface.py

Demonstrates the core asyncio client isolated from the GUI. Connects to ws://127.0.0.1:12345, actively listens for DeviceList, DeviceAdded, and DeviceRemoved events, dynamically mapping capabilities like VibrateCmd to a local dictionary.
