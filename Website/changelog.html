v2.12.0 - 2026-07-11

Adds the Animator Forge, a new avatar tool that both diagnoses broken animators and builds fully-rigged toggles for you. New avatar bases often ship with FX controllers that reference VRChat driver parameters like Seated without declaring them, which floods the SDK panel with "uses parameter which does not exist" errors. Animator Forge finds those and a whole family of related problems, and its Forge side generates a complete toggle - parameter, menu control, FX layer and states, and animation clips - in a single click, matched to your avatar's own Write Defaults convention. Editor tooling only; Built-in Render Pipeline / VRChat, as always.

Added

  • Animator Forge - Doctor: A new diagnostics engine that scans an avatar's playable-layer controllers plus its Expression Parameters and Menu, then lists ranked findings with one-click fixes. It catches transitions and blend trees that reference undeclared parameters (recognizing the full set of VRChat driver parameters such as Seated, AFK, VRMode and the Gesture values, and adding them back with the correct type), a broken mix of Write Defaults, menu controls bound to missing parameters, synced-parameter cost overflow, duplicate or mismatched parameters, dead zero-weight layers, and invalid transitions. Every finding has a Locate button and, where safe, a Fix, plus a "Fix all safe issues" batch for the unambiguous ones.
  • Animator Forge - Write Defaults Normalizer: The Write Defaults detection and fix follow the widely-used VRCFury model - grouping states as normal, Direct blend tree, or additive, taking the target from the FX layer's majority, and always forcing Direct blend trees and additive layers on. It reports the exact offending states and only changes anything when you ask it to.
  • Animator Forge - Empty Write-Defaults-Off Clip Check: Detects the SDK's "Write Defaults disabled where the animation clip is either missing or empty" warning (using VRChat's own scan logic), and one-click fixes it by assigning a shared inert clip with a single harmless property - which is what actually clears the warning, since a truly empty clip still reads as empty to the SDK.
  • Animator Forge - Rig Builder: The Forge tab builds complete, ready-to-use rigs with no manual Animator wiring. Five types are supported: GameObject toggle, blendshape toggle, blendshape slider (a radial dial), material swap, and exclusive group (a radio set where enabling one option disables the rest). Each build generates the Expression parameter, the menu control or submenu, the FX layer with states and transitions, and the animation clips, with new states matched to the avatar's Write Defaults convention. It is non-destructive - it reuses or creates the FX controller and expression assets, clones read-only sample controllers before touching them, and never deletes existing layers or parameters.
v2.11.0 - 2026-07-09

The Latex Ultra shaders reach 3.0.0 - a major overhaul. Hyper-realism gains a dedicated occlusion and baked-shadow map pair; high-gloss sparkle is gone by default; MatCaps grow to five layers with an avatar-lock Freeze, super-bright intensity and a fully reorganized panel; Emissions grow to five layers with consistent AudioLink; VRSL becomes its own tab; Light Volumes gain optional per-light speculars; and locked materials compile faster. Both shaders. Built-in Render Pipeline / VRChat only, as always. Every new feature is off or neutral by default so existing materials keep their look, but this is a big release - re-lock and spot-check your materials.

Added

  • Occlusion & Baked Shadow maps - new Lighting Detail section (Both Shaders): A dedicated Occlusion Map darkens ambient / indirect light in crevices, and a Baked Shadow Map paints permanent contact shadows that also cut direct light - both for added realism on the latex. Each has a channel picker and strength, and both share the Albedo sampler, so they add no sampler-budget cost. Off by default, so existing materials are unchanged.
  • Two more MatCap layers, five total (Both Shaders): MatCap 4 and MatCap 5 join 1-3, each a full matcap layer (texture, mask and channel, tint, rotation, intensity, blend mode, lighting mix, tiling, position, scroll). Off by default; no added sampler-budget cost.
  • MatCap Freeze - lock a matcap to the material (Both Shaders): A per-matcap Freeze slider stops a matcap sliding as the camera moves, so it reads as baked-in detail that turns naturally with the avatar instead of a mirror-like reflection. Default off (classic reflective matcap).
  • Three more Emission layers, five total (Both Shaders): Emission layers 3, 4 and 5 join 1 and 2, each with its own colour, map, mask channel and AudioLink band and amplitude. Off by default; no added sampler-budget cost.
  • Optional per-light Light Volume specular (Both Shaders): A new toggle routes Point Light Volumes through the light-source-size-aware per-light specular path for sharper, more accurate point-light glints on glossy latex, alongside a new Point Light Volume Shading strength control. Off by default (keeps the prior look).

Changed

  • Specular anti-aliasing on by default - no more sparkle (Both Shaders): High-gloss latex no longer shimmers or fizzes under motion. The specular anti-aliasing that already existed now defaults on, and an always-on roughness floor protects even previously-saved materials and distant surfaces. If you preferred the razor-sharp highlights, turn the anti-aliasing back down.
  • MatCaps reorganized into one panel (Both Shaders): The separate matcap tabs are consolidated into a single MatCaps section with Global Settings and Matcap 1-5 as sub-sections. Each matcap now has a Tiling & Movement sub-section (holding the Freeze control) and a dedicated Offsets sub-section, with clearly labelled position controls - Offset X moves side to side, Offset Y up and down (previously present but hidden inside an unlabelled field).
  • Brighter MatCaps (Both Shaders): MatCap Intensity now ranges up to 6 (was 2), so a matcap can push a strong, over-driven glow.
  • Emissions reorganized, AudioLink made consistent (Both Shaders): Each emission layer is now its own sub-section, and every layer's AudioLink band and amplitude sit inline with that layer and hide unless AudioLink is enabled. Previously only the second layer showed its AudioLink controls in this panel while the first layer's lived over in the AudioLink tab.
  • VRSL promoted to its own tab (Both Shaders): "Stage Lighting & VRSL" is now a top-level tab instead of being buried inside the AudioLink panel.
  • Faster locked-material compiles (Both Shaders): When a procedural effect is turned off (water drips, melting goo, the AudioLink HUD ring, fracture shards / trails), locked materials now drop that effect's geometry pass entirely at lock time, so locking and in-headset shader compilation are quicker. Animated toggles are respected - a pass is kept whenever its toggle is marked animated - so runtime toggling still works. Unlocked materials are unchanged.

Fixed

  • Light Volumes point-light bugfix and re-sync (Both Shaders): Re-synced the vendored Light Volumes to the current upstream revision, which fixes an off-by-one in the point-light attenuation lookup. The Light Volumes version stays 3 and every entry point the shaders use is unchanged, so the fix comes in transparently; no new samplers, keywords or variants, and existing worlds render unchanged.
v2.10.1 - 2026-07-05

A same-cycle hotfix that finishes the per-mesh bounds work from 2.10.0. The auto-fit could still mis-place the culling box on meshes carrying a Blender import scale (they would vanish up close), and its PhysBone swing inflation over-bloated body meshes genuinely weighted to a far-swinging bone. Both are resolved by fitting to Unity's own posed bounds and dropping the swing-reach heuristic entirely. Built-in Render Pipeline / VRChat only.

Added

  • Automated Animated Material Swap Re-Mapping (VixForge Quest Engine): The Quest conversion pipeline now natively supports animated material swaps. It scans both standard Animators and VRCAvatarDescriptor custom layers (Base and Special) for animation clips that swap materials at runtime. When detected, it clones the source AnimatorController (saving it as _Quest.controller) and deep-copies the affected .anim clips. It then rewires the object reference curves within the cloned clips to point to the new Quest-optimized materials, and recursively rebuilds the state machines and blend trees to reference the remapped clips. This completely eliminates the need for manual controller duplication and clip editing when porting avatars with material-based toggles or effects.

Fixed

  • Auto-Fit Bounds No Longer Mis-Places the Culling Box (Avatar Optimization Suite): The 2.10.0 fit snapshotted each mesh through BakeMesh and re-projected it with a hand-built matrix. On FBX meshes carrying a Blender import scale (e.g. 0.0254 or 2.54), that applied the scale a second time - collapsing the box and shoving its centre far off (a body read a centre near Y = -38 in root-bone space), so the mesh frustum-culled and disappeared the moment the camera drew close. It now reads Unity's own posed localBounds directly (via a momentary Update-When-Offscreen toggle), which is already in the root bone's space, so the fitted box always matches what Unity actually culls against.
  • PhysBone Swing Inflation Removed (Avatar Optimization Suite): The swing-reach inflation added in 2.10.0 still over-bloated compact meshes: a body legitimately weighted to a bone that a chain can swing about a metre received a guaranteed-worst-case box roughly double its true size, and its centre collapsed toward the hips. Guaranteed swing coverage is too conservative for static culling bounds, and swinging appendages (tail, hair, ears) are separate meshes with their own bounds anyway, so the swing-reach pass is removed. Each renderer now fits to its posed geometry plus a small (about 10%) margin for animation range, matching Unity's default tight bounds.
v2.10.0 - 2026-07-04

A combined release. VixForge Interactive and Enigma Industries join forces; the Latex Ultra shaders gain an in-scene four-layer decal system and two realistic-lighting refinements, re-sync to the current upstream VRC Light Volumes revision, and fix two Thry-locking regressions that dropped AudioLink and the procedural effect passes; and the Avatar Optimization Suite gets a ground-up overhaul with a real QEM mesh decimator, correct per-mesh bounds fitting, precise Locate navigation, selective texture targeting, and a per-avatar state flag. Built-in Render Pipeline / VRChat only, as always.

Added

  • News Tab & Enigma Industries Partnership (VixForge Hub): VixForge Interactive and Enigma Industries (the next chapter of Club Enigma) have partnered - two studios pooling tools, community, and immersive-world experience for VRChat. The VixForge Hub now opens on a new front-and-centre News tab with the full announcement and one-click buttons to the write-up, Enigma's Discord, and Enigma's VRChat group.
  • QEM Mesh Decimation (Avatar Optimization Suite): A real Quadric Error Metric edge-collapse decimator (Garland-Heckbert), the same class of algorithm as Blender's Decimate, replaces the old "smoothweld" that could only merge duplicate seam vertices. It drives each heavy mesh toward a triangle target while preventing face flips, rejecting sliver triangles, and preserving UV / normal seams, material (submesh) boundaries, and open borders. It locks the eye / mouth / teeth submeshes and the hand bones, interpolates UVs, vertex colours and bone weights across every collapse, and remaps every blendshape. Applied non-destructively (a new patched mesh, reversible with undo).
  • Decimation Target Slider (Avatar Optimization Suite): A new Decimation Target (tris / mesh) slider with a typed input box controls how aggressive the decimation is. Higher keeps more detail (softer); lower is smaller and more aggressive. Only meshes above the target are decimated, each down to the target.
  • Selective Texture Targeting (Avatar Optimization Suite): The blanket "downscale everything" pass is replaced by a per-texture targeting panel. Every texture gets its own checkbox, dimensions, a linear/data tag, and a Locate button, plus Select All / Deselect All and a live count, so you pick exactly which textures to resize instead of processing them all. Smart defaults pre-select only textures that need it.
  • Per-Avatar Optimization State Flag (Avatar Optimization Suite): A versioned per-avatar cache (mirroring the World Engine's lookup cache) records which Destructive Topology fixes have been applied, so a task clears from the list after a pass instead of re-listing forever. It only re-surfaces when the avatar actually changes or the target slider moves.
  • Four-Layer Decals (Both Shaders): A new Decals section places up to four independent decals on the material, each positioned right in the Scene view by dragging the gizmo handles. Per layer you get tint, position / scale / rotation (with optional spin), side offsets, a UV source, a packed RGBA mask channel, eight colour blend modes (Normal, Darken, Multiply, Lighten, Screen, Add, Subtract, Overlay), an emission glow, a smoothness offset so a sticker can read glossier or more matte than the latex, mirror and symmetry, and a clamp-or-tile toggle. All four decals share one texture sampler, so they add no sampler-budget cost. Off by default, so existing materials are unchanged.
  • Horizon Specular Occlusion (Both Shaders): A new control that fades reflections a normal map would otherwise leak through the surface at grazing angles, across reflection probes, Light Volumes, LTCGI and VRSL. Full by default; set to 0 to disable.
  • Specular Highlight Clamp (Both Shaders): A new control that caps direct point-light highlight intensity to tame sparkle on very glossy latex. Effectively off by default; lower it to clamp harder.

Changed

  • Realistic Lighting, Refined (Both Shaders): The Horizon Specular Occlusion and Specular Highlight Clamp controls above are surgical, opt-in additions to the existing realistic lighting model. Their defaults reproduce the previous look exactly, so nothing changes until you reach for them.
  • VRC Light Volumes Re-Sync (Both Shaders): Re-synced the vendored Light Volumes include across this cycle's upstream revisions - a structural performance pass that also reworked speculars to be more physically correct and light-source-size aware (larger point, spot, and area sources fall off more softly), followed by the current early-July revision that compiles faster, folds in upstream compile-error fixes, and swaps in a cheaper fast-exp path. The one entry point whose signature changed (the point-light sampler, whose parameters were reordered) was updated at both call sites to preserve the previous look exactly; every other entry point is unchanged. No new properties, samplers, textures, keywords, or shader variants, and existing materials and worlds render unchanged.

Fixed

  • "Locate" Now Jumps to the Real Offender (Avatar Optimization Suite): Every Locate button on a VRChat official performance warning used to just ping the avatar root. Each category now resolves to the actual worst offender - the heaviest renderer for the triangle count, the widest-reaching renderer for the bounding box, the renderer with the most material slots, the largest chain for PhysBone counts, the first matching component for collider / contact / light / particle / cloth / audio counts, and the heaviest texture for VRAM - so Locate takes you straight to the thing to fix.
  • Per-Mesh Bounds Fit Was in the Wrong Space (Avatar Optimization Suite): On avatars whose body is skinned across a scaled armature, the auto-fit produced a culling box roughly twice the correct size and mis-centred, because it fit against the renderer's own transform while Unity stores and culls a Skinned Mesh Renderer's bounds in the root bone's space. It now resolves the true root bone and bakes the mesh through Unity's own skinner, so the fitted box matches Unity's default tight bounds.
  • PhysBone Swing Inflation Over-Bloated Static Meshes (Avatar Optimization Suite): The bounds swing-reach inflation was applied whenever a mesh touched any bone in a PhysBone chain (including the anchored root) and tested against the whole skeleton, so a body would get inflated by an unrelated mane or tail chain it wasn't even weighted to. Inflation is now filtered to bones the mesh actually has vertex weight on, and scales with how far down the swinging chain that weight sits.
  • AudioLink No Longer Fails to Compile on Locked Materials (Both Shaders): Locking a material with the Poiyomi / Thry optimizer (required before an avatar upload) could drop AudioLink from every shader pass except the first, so affected materials failed to compile with an "undeclared identifier" error. The optimizer inlines each shared include only once per shader, and the material had previously pulled the AudioLink helper in separately inside each pass, so only the first pass kept it. The AudioLink include is now hoisted into a single shared block that the engine applies to every pass, so all passes get it after locking. Affects both shaders; re-lock any affected material to pick it up. No new controls, no cost, and unlocked materials are unchanged.
  • Locking No Longer Breaks the Procedural Effect Passes (Both Shaders): Locking a material with the Thry optimizer (required before an avatar upload, so unlocked shaders are not stripped from the build) was silently disabling the geometry stage of the procedural effect passes - the water drips, the melting goo, the AudioLink HUD ring, and the fracture shards and trails - leaving them to render incorrectly or fail to compile. The shader now tells the optimizer to keep its geometry passes when locking, so every effect survives the lock intact. No new controls, no cost, and unlocked materials are unchanged; re-lock any affected material to pick up the fix.

v2.8.0 - 2026-06-26

The big lighting and integration refresh: matcaps gain a real blend model and a third layer, LTCGI gets per-lobe modes and colour tints, Light Volumes moves to upstream 3.x, AreaLit is retired, TechnicallySane lighting goes public (TSLCE-first with GlobalRGB fallback), and a stack of point-light / parallax / droplet rendering bugs are fixed. Build times are heavily optimized via dynamic branching, and the inspector is reorganised into one collapsible section per feature. Built-in Render Pipeline / VRChat only, as always.

Added

  • Dynamic Branching (Both Shaders): All heavy build-time features and integrations are now locked behind Unity [Branch], which tells the compiler not to include that feature if it is disabled, reducing build times dramatically.
  • Third MatCap Layer & Global MatCap Settings (Both Shaders): A third independent matcap layer with its own texture, mask, channel, tint, rotation, tiling, scroll, blend mode, and lighting mix. A new GLOBAL MATCAP SETTINGS group adds MatCap Projection Bias, a shared 0-1 control that blends every matcap layer between camera-aligned and mesh-UV-aligned projection to dial out the "sliding" feel.
  • LTCGI Modes, Colour Tints & Auto-Suppress (Both Shaders): New _UseLTCGI runtime gate, an LTCGI Mode dropdown (Both / Diffuse Only / Specular Only), and independent diffuse and specular tints. When a world bakes its LTCGI into the Light Volumes atlas, the suit's direct LTCGI sampling now auto-suppresses (asint(_UdonLightVolumesWithLTCGI) != 0) to prevent double lighting.
  • Global Metallic / Smoothness (Both Shaders): New sliders scale packed map metallic and smoothness across the entire surface. Metallic defaults to 0 and smoothness defaults to 0.5.
  • Light Volumes Runtime Gate (Both Shaders): New _UseLightVolumes toggle allows VRCFury to switch the entire Light Volumes path on or off at runtime without a recompile. The editor now derives the keywords from these float gates.
  • TechnicallySane Lighting, TSLCE-First (Both Shaders): Full TechnicallySane integration reads the modern TSLCE control texture as the primary path and falls back automatically to the legacy GlobalRGB broadcast in older worlds. Controlled by a single toggle and existing tint controls. Now fully supported in both shaders, including SPS.
  • 3D Water Droplets on the SPS suit: The geometry-shader droplet pass (real water beads that swell, pinch off, fall, and dry) is now present on the SPS shader. It is a geometry stage and entirely independent of tessellation.
  • Tessellation-free Melting Goo on the SPS suit: A new geometry-shader goo pass extrudes downward-hanging, billboarded melt tendrils where the Goo mask is active. The SPS suit gets these geometry tendrils instead of surface tessellation.
  • Integration Attribution Help Boxes (Both Shaders): Each integration section now includes a clickable attribution box linking to the upstream project (RED_SIM, _pi_/pimaker, llealloo, AcChosen), plus a conditional reminder that TechnicallySane only functions in compatible worlds.

Changed

  • Surface-Relative MatCap Blend Model (Both Shaders): The matcap layers now composite through proper multiply and add carriers (finalColor = finalColor * MatcapMul + MatcapAdd * litEnv). Multiply and Replace now tint, darken, or overwrite the surface correctly inside the layer's mask. Add is mathematically unchanged.
  • VRC Light Volumes Upstream 3.x (Both Shaders): Updated to the latest upstream 3.x release and adapted the surf call sites. The regular SH excludes additive volumes. No new material properties.
  • Render Mode Dropdown (Both Shaders): Rendering Mode uses Thry's [ThryWideEnum] drawer so the Opaque, Cutout, Fade, and Transparent dropdown renders correctly in the inspector.
  • Sampler-Budget Headroom (Both Shaders): Five fragment-only maps now borrow _MainTex's sampler, freeing up to five sampler registers.
  • Inspector Reorganised by Feature + Shader Docs Rebuild: The material inspector is now organised into one collapsible Thry section per feature instead of the previous six tabs. The public shader documentation was rebuilt to match.

Removed

  • AreaLit Integration (Both Shaders): Removed AreaLit entirely including keywords, properties, includes, and broadcasters. It produced artifacts in worlds with a broadcaster but no active light data. LTCGI and VRC Light Volumes 3.x cover area lighting cleanly.

Fixed

  • Parallax Depth Could Black Out the Surface (Both Shaders): The self-shadow raymarch previously started its ray below the height field and tracked the lit margin, locking flat areas to roughly 3% light. The trace was rewritten to use the raw height and accumulate true occlusion so flat surfaces return full light.
  • Every 3D Droplet Discarded (Base Shader): A smooth-minimum intersection collapsed the droplet bead to zero, causing all droplets to be discarded. Switched to a smooth-maximum union so the bead and neck silhouette renders correctly.
  • Duplicate Toolbar Sections: When using multiple shaders or tools under the VixForge Interactive brand, tools previously created their own redundant "VixForge Tools" editor menus. These have now been merged cleanly under VixenTools/VixenWear and VixenTools/VixenWorld respectively.
v2.7.0 - 2026-06-19

The material inspector moves to the Thry shader editor, and the new VRC Light Volumes V3 point / spot / area lights get a stability pass so their baked shadows and volumetrics stop smearing. Inspector and Light Volumes only - the core lighting model is unchanged.

Added

  • Thry Shader Inspector (Both Shaders): The hand-written tabbed material inspector was retired in favour of the Thry shader editor. You get Thry's native per-section reset / copy / paste, presets, render-queue and instancing controls, locale and notes, plus a one-click Lock In Optimized Shader optimiser button, the VixForge title bar, and a footer link row (Website / Discord / X / GitHub / Ko-fi). ThryEditor (`de.thryrallo.thryeditor`) is now a required dependency - it is intentionally not bundled, to avoid duplicate-drawer conflicts with other Thry-based shaders such as Poiyomi (which already ships it). Editor and property-layout change only: no HLSL, lighting, pass, sampler, or variant change.
  • Light Volumes V3 Stability Controls (Both Shaders): Two new runtime sliders on the Light Volumes group - `Shadow / Volumetric Normal Stability` (`_LV_Pt_Stability`, default 1.0) and `Clearcoat Specular Tightness` (`_LV_CC_Tight`, default 0.5). No new samplers, keywords, or shader variants.

Changed

  • Materials Must Be Locked Before Upload: With the Thry optimiser adopted, unlocked materials carrying the optimiser button are stripped from the build and render pink. Locking happens automatically on avatar / world upload, and you can also lock manually from the inspector to preview the final result. This replaces the old bespoke build-time keyword and variant-stripping tooling.

Fixed

  • Smeared V3 Point / Spot / Area Shadows (Both Shaders): The new Light Volumes V3 point, spot, and area lights - and their per-light EVSM baked shadows - read smudged because they were shaded with the parallax-raymarched, detail-perturbed normal, so surface noise leaked straight into the shadowcasting and volumetrics. They now use a stable geometric normal (set by `_LV_Pt_Stability`), while the SH diffuse and the reflective speculars keep the full bumped normal. Lower the slider to feed surface bump back into the point-light shadow mask.
  • Clearcoat Light-Volume Highlight Wash (Both Shaders): A bright point or area light made the clearcoat's Light Volume specular bloom into a broad wash because the upstream lobe has a high roughness floor. `_LV_CC_Tight` now shrinks that lobe down to a tight glint; the contribution strength still comes from the existing Clearcoat Specular mix.
v2.6.0 - 2026-06-15

Realtime point and spot lights light the suit again, and VRC Light Volumes is upgraded to V3 with its full point / spot / area-light set (including the proper "TV GI" path). Built-in Render Pipeline / VRChat only, as always.

Added

  • VRC Light Volumes V3 (Both Shaders, `LIGHTVOLUMES_ENABLE`): Upgraded the vendored Light Volumes include from V2 to upstream V3. The suit now receives Point Light Volumes in addition to baked volumes: point lights, spot lights (parametric / attenuation-LUT / projected cookie), cubemap-tinted point lights, and quad area lights - all projected into the same L1-SH path the volumes already used, so they flow through the existing diffuse + specular machinery and respond to the existing `_LV_*` controls. The surface now passes its shaded world normal so V3's normal-mask term applies. No new material properties.
  • TV GI via LV V3 Area Lights (Both Shaders): The "TV lights the room" effect is back, now done correctly through V3 area lights instead of the old raw-texture tint that was pulled in 2.5.0. A world author points a Point Light Volume (AreaLight type) at a video screen's RenderTexture; the LV V3 runtime feeds its colour into the quad-light SH and the suit picks it up automatically, with no per-material setup. Appears only in worlds running the LV V3 runtime; older / no-LV worlds fall back to deringed light probes via the version gate.
  • Point Light Volume Shadows (Both Shaders): V3's per-light EVSM shadows (cubemap and single-slice) are enabled. To stay inside the 16-sampler budget, the shadow texture array reuses the existing Light Volumes sampler, so V3 adds zero net sampler registers over V2.

Fixed

  • Point / Spot Lights No Longer Leave the Surface Dark (Both Shaders): The main lighting pass carried `noforwardadd`, which deletes Unity's generated ForwardAdd pass. In the Built-in pipeline, point and spot lights are shaded per-pixel only in ForwardAdd, so with it removed the surface only picked them up as a weak per-vertex / SH approximation and read as unlit under them. Removed `noforwardadd`; the GI function and BRDF are split so the additive pass accumulates only direct-light terms, while all indirect / emissive terms (ambient, reflection probe, Light Volumes, LTCGI, AreaLit, VRSL-GI, matcap, emission) and their texture samples are gated to the base pass via `UNITY_PASS_FORWARDADD` - so the additive variant stays well under the 16-sampler cap, which is why `noforwardadd` had been used as a shortcut. Point lights illuminate without cookies / cube-shadows (those variants remain skipped to bound the variant count).
  • VixenWorld Surface Ultra Parity: The world-surface shader received the same three fixes: ForwardAdd enabled (with the same base-pass guards), VRC Light Volumes V3, and the Tessellation Detail control (its `_Tess_Edge` slider had the identical inverted / uncapped problem fixed in the latex shader in 2.5.0, now `_Tess_Detail`, range 0-1, capped). Existing world materials reset to the new `0.5` tessellation default.
v2.5.0 - 2026-06-13

Full world-lighting integration pass: the latex now reacts to every supported stage / area-light system, and the legacy TV-GI tint is gone. Every integration is fail-safe - it strips or no-ops cleanly in worlds that don't have the system. Built-in Render Pipeline / VRChat only (HDRP/URP out of scope by design).

Added

  • AreaLit Area-Light Support (Both Shaders, `AREALIT_ENABLE`): The latex now receives PiMaker AreaLit area lights, the same role as LTCGI. AreaLit ships no scene-wide broadcast, so the suit intercepts it at the GI level like LTCGI via a small world-side helper (`AreaLitGlobalBroadcaster.cs`, UdonSharp) that publishes the LightCam data as scene globals - every avatar in the world is lit automatically, with no per-material assignment. A per-material pair (`_AreaLit_LightMesh` / `_AreaLit_LightTex0`) remains as a manual fallback when no broadcaster is present. Zero new sampler registers; keyword-gated on `_AreaLit_Int > 0` and stripped (zero cost) when off. On the INTEGRATION tab.
  • VRSL GI Wash (Both Shaders): A new additive coloured stage wash on top of the existing VRSL stage-hijack. Instead of overriding emission, it spills the DMX fixtures' colour onto the suit as real light (the stage lighting you up), decoded from the same DMX grid + channel offsets the Color Hijack reads. Controls `_VRSL_GI_Int` / `_VRSL_GI_Spec` / `_VRSL_GI_Sat` on the STAGE tab. 🎨 VixenTools/Latex Suit Ultra: Substance Painter Workflow & Setup

To achieve the intended high-fidelity raymarched depth, clearcoat iridescence, and micro-shadowing, your PBR textures must be packed correctly before importing to Unity.

1. Substance Painter Export Setup (The Packed PBR Map)

The _MetallicGlossMap slot requires a highly specific 4-channel texture packing to optimize VRAM and shader instruction counts:

  • Red Channel (R): Metallic
  • Green Channel (G): Ambient Occlusion (AO)
  • Blue Channel (B): Height / Displacement (Used for Tessellation and Parallax Raymarching)
  • Alpha Channel (A): Smoothness (Inverted Roughness / Glossiness)

How to configure the Export Template in Substance Painter:

  1. Open Export Textures -> Output Templates.
  2. Create a new R+G+B+A texture map. Name it [TextureSet]_PackedPBR.
  3. Drag the Metallic map into the R slot (From Grayscale).
  4. Drag the Mixed AO map into the G slot (From Grayscale).
  5. Drag the Height map into the B slot (From Grayscale).
  6. Drag the Glossiness map into the A slot (From Grayscale). Note: If you use a Roughness workflow, drag Roughness into the A slot and select "Invert".
  7. Save the template and export your textures.

2. Unity Shader Configuration

  • Albedo / Alpha: Slot your Base Color into _MainTex. The Alpha channel controls the _CutOff transparency.
  • Packed PBR: Slot the newly exported [TextureSet]_PackedPBR into the Packed PBR Map slot. Ensure the texture in Unity has sRGB (Color Texture) unchecked (Linear format).
  • Normal Map: Slot your standard DirectX/OpenGL normal map into _BumpMap.

3. Advanced Features Integration

  • Tessellation & Parallax: Adjust the _DisplacementStrength (driven by your B channel) and _Parallax to control physical depth and micro-shadowing.
  • Thin Film Interference: Modify _ThinFilmThickness to shift the iridescent pearlescent color tone.
  • AudioLink: Check Enable AudioLink to dynamically drive Iridescence via the Bass band (_AudioLinkFilmMod) and Emission via the Treble band.
